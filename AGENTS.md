# Repository Instructions

- Complete one functional task per daily session. The task determines the commit count.
- Commit after each 10 changed nonblank lines of handwritten source or test code. Use the nearest buildable boundary and commit any remainder at task completion. Generated output, dependency lockfiles, and formatting-only changes do not count toward the checkpoint.
- Give each commit a descriptive message. Run the most relevant available checks and push each checkpoint before continuing.
- Keep commits buildable and preserve published history. Avoid empty, cosmetic-only, and duplicate commits.
- Never commit secrets, credentials, personal health information, identifiable resident data, or unapproved client documents.
- Use public, synthetic, or explicitly authorized de-identified content during discovery and MVP development.
- Treat extracted obligations and policy coverage as provisional review aids, never legal advice or compliance certification.
- Preserve source URL, jurisdiction, version, effective date, retrieval time, checksum, and exact citation spans wherever applicable.
- Prefer deterministic validation, explicit abstention, least privilege, tenant isolation, deletion controls, and auditable human approval.
- Update `docs/PROGRESS.md` after each meaningful workstream and replace `docs/TODO.md` with a concrete plan for the next calendar day before ending a daily session.
- Keep generated artifacts isolated from handwritten changes and explain generation commands in the commit message or nearby documentation.
